# 本地构建环境改造与全栈认知提升

## 背景

接手一个 20+ 微服务的老项目，技术栈以 Vue、Angular 为主，微服务架构，使用 CF2 鉴权机制。原有本地开发体验极差：

- 每次修改代码后需要部署到 beta 环境才能验证
- 本地无法调试接口，请求直接打到远程服务，鉴权不通
- 需求开发和 bug 修复效率很低，一个简单改动要走完整个部署流程

## 做了什么

**改写本地构建配置，让本地开发环境完整跑起来。**

核心工作：

1. **本地服务器搭建**——在前端项目中启动一个本地 Node.js 服务器，配合 Webpack 构建打包的产物，替代原有的"改完就部署"流程
2. **请求代理与拦截**——本地服务器代理远程服务通信，拦截请求并做特殊处理（鉴权注入、请求转发、响应改写），让本地能完整模拟线上请求链路
3. **CF2 鉴权方案适配**——理解 CF2 鉴权的设计理念，搞清楚后端需要怎样的 cookie 才会返回真实数据，在本地构造合法的鉴权上下文
4. **Webpack 构建配置改造**——修改 Webpack devServer 配置、proxy 规则、output 产物路径等，让本地构建产物能正确对接本地服务器

## 技术收获

### Webpack 的使用方式与原理
- 理解了 Webpack 的模块打包机制：entry → loader → plugin → output 的完整链路
- 掌握了 devServer 的工作原理：内存文件系统、HMR 热更新、proxy 代理
- 学会了如何改造构建配置来适配不同的开发环境需求

### 服务器的运行原理
- 知道了怎么在前端项目中启动一个 Node.js 服务器
- 理解了 HTTP 请求/响应的完整处理流程
- 掌握了请求拦截、代理转发、响应改写的实现方式

### Node.js 技术应用的深化
- 从"会用"到"理解原理"：知道了 Node.js 怎么处理请求响应，怎么在中间层做逻辑拦截
- 理解了前端工程化中"本地开发服务器"这个角色的定位和价值

### CF2 鉴权方案的设计理念
- 理解了企业级鉴权方案的设计思路：cookie 机制、token 传递、服务间鉴权链路
- 知道了后端对 cookie 的校验逻辑，哪些字段是必须的，格式要求是什么
- 对于跟后端接口交互有了更加深刻的理解：不只是"调接口"，而是理解整个请求链路上的每一个环节

## 成果

- 本地开发环境完整跑通，修改代码后本地即时验证，不再需要每次部署到 beta 环境
- 本地可以调试接口，请求链路完整模拟线上行为
- 需求开发和 bug 修复效率大幅提升，从"改-部署-验证"的分钟级循环缩短到秒级
- 个人技术认知从纯前端扩展到"前端 + 本地服务 + 鉴权 + 接口交互"的全链路理解
